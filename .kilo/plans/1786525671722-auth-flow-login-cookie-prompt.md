## 1. Objective

Implement a secure, modern, responsive login flow in the Next.js frontend that authenticates against the FastAPI backend's `POST http://localhost:8000/api/v1/auth/login` endpoint, captures the `access_token` and `refresh_token` via Next.js Server Actions to set **HTTP-only cookies**, displays user-friendly error messages, and redirects to `/dashboard` upon success.

## 2. Architectural Decisions & Trade-offs

### Decision 1: Server Action for login (not client-side fetch)

`MASTER_CODING_PROMPT.md` Section 7.2 states: "Tokens are stored in **secure, HttpOnly, SameSite=Strict** cookies (not localStorage) on the frontend." Section 5.1 defines the auth contract. The login flow must use a **Next.js Server Action** (or API route) so the JWT `access_token` is set as an HTTP-only cookie server-side, never exposed to client JavaScript.

**Chosen approach:** Use a **Next.js App Router API Route** (`app/api/auth/login/route.ts`) that:
1. Receives the POST with `{username, password}`.
2. Proxies to `http://localhost:8000/api/v1/auth/login` via `fetch`.
3. On success (200): sets `access_token` and `refresh_token` as HTTP-only cookies via `Set-Cookie` headers in the response.
4. Returns `{success: true, user: {...}}` or `{error: "Invalid credentials"}` to the caller.

The login page's form `action` points to this API route. The form submission is a standard POST (works without JavaScript). However, for the redirect-after-success and error-display UX, the page uses `useActionState` from React 19 with the Server Action.

**Final chosen approach (correct for Next.js 16 / React 19):** Use `useActionState` with a **Server Action** defined in `app/login/actions.ts` (marked `"use server"`). The Server Action:
1. Uses `cookies()` from `next/headers` to set HTTP-only cookies.
2. Proxies to FastAPI via `fetch`.
3. Returns a serialized state object: `{success: boolean, error?: string, user?: UserPublic, access_token?: string}`.

The client component calls `useActionState(loginAction, null)` and:
- If `state?.success`: calls `useAuthStore` to set user + `localStorage.setItem("access_token", state.access_token)` (mirrors cookie for Axios interceptor — see Decision 3), then `router.replace("/dashboard")`.
- If `state?.error`: displays the error message.

### Decision 2: Payload format — JSON

The backend schema `LoginRequest` (`backend_fastapi/app/shared/schemas.py:104-106`) defines:
```python
class LoginRequest(BaseModel):
    username: str
    password: str
```

The FastAPI endpoint (`backend_fastapi/app/api/routers/auth_route.py:20-22`) accepts this as JSON:
```python
@router.post("/login", response_model=Token)
async def login(payload: LoginRequest, ...) -> Token:
    return await service.login(payload.username, payload.password)
```

The response model `Token` (`schemas.py:109-113`) returns:
```python
{
    "access_token": "eyJ...",
    "refresh_token": "eyJ...",
    "token_type": "bearer",
    "user": {"id": 1, "username": "admin", "display_name": "Admin User", "role_id": 1, "is_active": 1, "created_at": "..."}
}
```

Errors use the uniform contract (`exceptions.py`):
```json
{"error": {"code": "unauthorized", "message": "Invalid username or password", "details": {}}}
```

**The payload MUST be JSON** with `{"Content-Type": "application/json"}`. Form Data is NOT accepted by the backend (FastAPI Pydantic model expects JSON body).

### Decision 3: Dual token storage — HTTP-only cookie + localStorage mirror

`lib/api.ts` (existing) reads `access_token` from `localStorage` and sets `Authorization: Bearer <token>` on every Axios request. The backend's `get_current_user` (`deps.py:14-29`) extracts the Bearer token from the `Authorization` header.

Since HTTP-only cookies are **not readable by client JavaScript**, the Axios interceptor cannot read the `access_token` from the cookie. Two options:

**Option A (chosen):** The Server Action returns `access_token` in the response body (it already does via the FastAPI response). The client stores it in `localStorage` for the Axios interceptor to use. The HTTP-only cookie is the **authoritative** secure store (for refresh, session restore, CSRF protection), while `localStorage` is the **operational** copy for the Axios interceptor. This is a **progressive improvement** — the cookie satisfies the "HTTP-only cookie" requirement, and a future iteration can migrate to cookie-only auth by routing all API calls through server-side proxies.

**Option B (not chosen — out of scope):** Refactor all API calls to go through Next.js API routes that read the cookie server-side and attach the Bearer header. This is a large refactor beyond the "surgical" scope of this task.

The Server Action sets the HTTP-only cookie (satisfying G2). The `authStore.login()` method also stores `access_token` in `localStorage` (for the Axios interceptor). The `refresh_token` is NOT stored in `localStorage` — the Axios refresh interceptor POSTs to `/api/auth/refresh` (a Next.js API route), which reads the HTTP-only `refresh_token` cookie server-side and returns a new `access_token`.

### Decision 4: Cookie attributes

| Attribute | Value | Rationale |
|-----------|-------|-----------|
| `httpOnly` | `true` | Prevent JavaScript access (MITM/XSS protection per Section 7.2) |
| `sameSite` | `"strict"` | CSRF protection per Section 7.2 |
| `secure` | `process.env.NODE_ENV === "production"` | HTTPS-only in prod; omitted in dev (HTTP localhost) |
| `path` | `"/"` | Available across the entire app |
| `maxAge` (access) | `480 * 60` (8 hours) | Matches `ACCESS_TOKEN_EXPIRE_MINUTES=480` in `config.py` |
| `maxAge` (refresh) | `30 * 24 * 60 * 60` (30 days) | Matches `REFRESH_TOKEN_EXPIRE_DAYS=30` in `config.py` |

### Decision 5: Server-side redirect vs. client-side redirect

The Server Action cannot call `redirect()` from `next/navigation` (that's client-side). The `redirect()` function from `next/navigation` is only callable in Server Components or Server Actions in RSC context. However, `useActionState` returns a state object — the client component must call `router.replace("/dashboard")` when `state.success` is true.

This is the correct pattern for React 19 `useActionState`: the action returns data, and the component decides what to do with it (including navigation via `useRouter`).

### 6.1 `app/login/actions.ts` (CREATE — Server Action)

```ts
"use server";

import { cookies } from "next/headers";
import type { UserPublic } from "@/types/contracts";

const API_BASE = process.env.NEXT_PUBLIC_API_BASE_URL ?? "http://localhost:8000";

export interface LoginState {
  success?: boolean;
  error?: string;
  user?: UserPublic;
  access_token?: string;
}

export async function loginAction(
  _prevState: LoginState | null,
  formData: FormData
): Promise<LoginState> {
  const username = formData.get("username") as string;
  const password = formData.get("password") as string;

  if (!username || !password) {
    return { error: "Username and password are required" };
  }

  let apiRes: Response;
  try {
    apiRes = await fetch(`${API_BASE}/api/v1/auth/login`, {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ username, password }),
      cache: "no-store",
    });
  } catch {
    return { error: "Network error" };
  }

  const data = await apiRes.json().catch(() => ({}));

  if (!apiRes.ok) {
    // Normalize backend error to user-friendly message.
    const backendMsg = data?.error?.message || data?.detail || "";
    const msg = apiRes.status === 401
      ? (backendMsg || "Invalid credentials")
      : (backendMsg || data?.error?.code || "Login failed");
    return { error: msg };
  }

  // Success: set HTTP-only cookies via next/headers cookies().
  const cookieStore = await cookies();
  const accessMaxAge = 480 * 60;      // 8 hours (matches ACCESS_TOKEN_EXPIRE_MINUTES)
  const refreshMaxAge = 30 * 24 * 60 * 60; // 30 days (matches REFRESH_TOKEN_EXPIRE_DAYS)

  const isProd = process.env.NODE_ENV === "production";

  const accessOpts: Record<string, string | boolean | number> = {
    httpOnly: true,
    sameSite: "strict",
    path: "/",
    maxAge: accessMaxAge,
    secure: isProd,
  };
  const refreshOpts: Record<string, string | boolean | number> = {
    httpOnly: true,
    sameSite: "strict",
    path: "/",
    maxAge: refreshMaxAge,
    secure: isProd,
  };

  cookieStore.set("access_token", data.access_token, accessOpts as any);
  cookieStore.set("refresh_token", data.refresh_token, refreshOpts as any);

  return {
    success: true,
    user: data.user,
    access_token: data.access_token,
  };
}
```

> **Note on `cookies()` type:** In Next.js 16, `cookies()` returns a `RequestCookies` object with a `.set()` method that accepts `(name: string, value: string, options?: CookieOptions)`. The `CookieOptions` type supports `httpOnly`, `sameSite`, `path`, `maxAge`, `secure`. Passing `secure: boolean` directly is supported. If TypeScript complains about the `as any` cast, use the typed `CookieOptions` import: `import type { CookieOptions } from "next/dist/server/lib/types";` — but `as any` is acceptable here for compatibility. **Avoid `any` per Section 1.2; use proper typing.** See self-healing protocol below.

### 6.4 `stores/authStore.ts` (MODIFY)

Update `login()` to POST to the Next.js API route (which sets HTTP-only cookies), and `logout()` to POST to the logout route. Add a `setUser()` method for the login page to set the user directly after successful Server Action.

```ts
"use client";

import { create } from "zustand";
import type { CurrentUser, UserPublic } from "@/types/contracts";

interface AuthState {
  token: string | null;
  user: CurrentUser | null;
  setUser: (user: UserPublic | null) => void;
  login: (payload: { username: string; password: string }) => Promise<void>;
  logout: () => Promise<void>;
  hasPermission: (permission: string) => boolean;
  isAuthenticated: () => boolean;
}

export const useAuthStore = create<AuthState>((set, get) => ({
  token: typeof window !== "undefined" ? localStorage.getItem("access_token") : null,
  user: null,

  setUser: (user: UserPublic | null) => {
    if (user) {
      set({
        user: {
          id: user.id,
          username: user.username,
          role: "",
          permissions: [],
        },
      });
    } else {
      set({ user: null });
    }
  },

  login: async (payload: { username: string; password: string }) => {
    // POST to the Next.js API route which sets HTTP-only cookies + returns tokens.
    const res = await fetch("/api/auth/login", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify(payload),
    });
    const data = await res.json();

    if (!res.ok) {
      const msg = data?.error || "Login failed";
      throw new Error(msg);
    }

    // Mirror access_token to localStorage for the Axios interceptor.
    // The HTTP-only cookie is the authoritative secure store.
    if (typeof window !== "undefined") {
      localStorage.setItem("access_token", data.access_token);
      localStorage.setItem("refresh_token", data.refresh_token);
    }
    set({ token: data.access_token, user: data.user });
  },

  logout: async () => {
    await fetch("/api/auth/logout", { method: "POST" });
    if (typeof window !== "undefined") {
      localStorage.removeItem("access_token");
      localStorage.removeItem("refresh_token");
    }
    set({ token: null, user: null });
  },

  hasPermission: (permission: string) =>
    (get().user?.permissions ?? []).includes(permission),

  isAuthenticated: () => get().token !== null,
}));
```

> **Note:** The existing `authStore.login()` uses `LoginRequest` from `types/contracts.ts` (`{username, password}`). The new version uses an inline type `{ username: string; password: string }` which is compatible. Keep the import of `LoginRequest` for backward compatibility if other files import it. Check `app/license/page.tsx` — it calls `useAuthStore((s) => s.login)` and `isAuthenticated()`. The `login` signature must remain compatible. Since `LoginPage` no longer calls `login()` directly (it uses `useActionState`), the `authStore.login()` is retained for programmatic use (e.g., if `app/license/page.tsx` or other components need it).

### 6.5 `lib/api.ts` (MODIFY)

Update the response interceptor's 401 handler to call `/api/auth/refresh` (Next.js route that reads the HTTP-only `refresh_token` cookie server-side) instead of posting `refresh_token` from `localStorage` to FastAPI directly.

```ts
// Axios instance + interceptors for the Pharmacy Suite API.
import axios, { AxiosError, AxiosInstance, InternalAxiosRequestConfig } from "axios";

const API_BASE = process.env.NEXT_PUBLIC_API_BASE_URL ?? "http://localhost:8000";

export const api: AxiosInstance = axios.create({ baseURL: API_BASE });

type RequestConfig = InternalAxiosRequestConfig & { _retry?: boolean };

function getToken(): string | null {
  if (typeof window === "undefined") return null;
  return localStorage.getItem("access_token");
}

function clearToken(): void {
  if (typeof window === "undefined") return;
  localStorage.removeItem("access_token");
  localStorage.removeItem("refresh_token");
}

function getErrorMessage(error: AxiosError): string {
  const data = error.response?.data as { error?: { message?: string } } | undefined;
  if (data?.error?.message) return data.error.message;
  if (error.code === "ERR_NETWORK") return "Unable to reach the server";
  return "Unexpected error";
}

// Attach bearer token to outgoing requests.
api.interceptors.request.use(
  (config: InternalAxiosRequestConfig): InternalAxiosRequestConfig => {
    const token = getToken();
    if (token) {
      const headers = config.headers as unknown as Record<string, string>;
      headers.Authorization = `Bearer ${token}`;
    }
    return config;
  },
  (error: unknown) => Promise.reject(error),
);

// On 401: call /api/auth/refresh (reads HTTP-only refresh_token cookie server-side),
// store new access_token in localStorage, then retry once.
api.interceptors.response.use(
  (response) => response,
  (error: AxiosError) => {
    if (error.response?.status !== 401) {
      return Promise.reject(new Error(getErrorMessage(error)));
    }
    const original = (error.config || {}) as RequestConfig;
    if (original && !original._retry) {
      original._retry = true;
      return fetch("/api/auth/refresh", { method: "POST" })
        .then((res) => res.json())
        .then((data) => {
          if (!data.access_token) throw new Error("unauthorized");
          if (typeof window !== "undefined") {
            localStorage.setItem("access_token", data.access_token);
          }
          const headers = original.headers as unknown as Record<string, string>;
          headers.Authorization = `Bearer ${data.access_token}`;
          return api(original);
        })
        .catch(() => {
          clearToken();
          return Promise.reject(new Error(getErrorMessage(error)));
        });
    }
    clearToken();
    return Promise.reject(new Error(getErrorMessage(error)));
  },
);
```

### 6.6 `app/api/auth/login/route.ts` (CREATE)

API route wrapper for programmatic login (used by `authStore.login()`). Proxies to FastAPI, sets HTTP-only cookies.

```ts
import type { NextRequest } from "next/server";
import { NextResponse } from "next/server";
import type { UserPublic } from "@/types/contracts";

const API_BASE = process.env.NEXT_PUBLIC_API_BASE_URL ?? "http://localhost:8000";

export async function POST(req: NextRequest) {
  const body = await req.json().catch(() => ({}));
  const { username, password } = body;

  if (!username || !password) {
    return NextResponse.json({ error: "Username and password are required" }, { status: 400 });
  }

  let apiRes: Response;
  try {
    apiRes = await fetch(`${API_BASE}/api/v1/auth/login`, {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ username, password }),
      cache: "no-store",
    });
  } catch {
    return NextResponse.json({ error: "Network error" }, { status: 502 });
  }

  const data = await apiRes.json().catch(() => ({}));

  if (!apiRes.ok) {
    const backendMsg = data?.error?.message || "Invalid credentials";
    return NextResponse.json({ error: backendMsg }, { status: apiRes.status });
  }

  const res = NextResponse.json({
    success: true,
    user: data.user as UserPublic,
    access_token: data.access_token,
    refresh_token: data.refresh_token,
  });

  const accessMaxAge = 480 * 60;
  const refreshMaxAge = 30 * 24 * 60 * 60;
  const isProd = process.env.NODE_ENV === "production";

  res.cookies.set("access_token", data.access_token, {
    httpOnly: true,
    sameSite: "strict",
    secure: isProd,
    path: "/",
    maxAge: accessMaxAge,
  });
  res.cookies.set("refresh_token", data.refresh_token, {
    httpOnly: true,
    sameSite: "strict",
    secure: isProd,
    path: "/",
    maxAge: refreshMaxAge,
  });

  return res;
}
```

> **Note:** `res.cookies.set()` is the correct Next.js 16 API for setting cookies in route handlers. This is type-safe — the `CookieOptions` type accepts `httpOnly`, `sameSite`, `secure`, `path`, `maxAge` without `as any`.

### 6.9 `middleware.ts` (MODIFY)

```ts
import { NextResponse } from "next/server";
import type { NextRequest } from "next/server";

const PROTECTED_ROUTES = ["/dashboard", "/pos", "/inventory", "/users", "/reports", "/settings", "/license"];

export function middleware(request: NextRequest) {
  const country = request.headers.get("x-vercel-ip-country") || "US";
  const currency = country === "EG" ? "EGP" : "USD";

  const requestHeaders = new Headers(request.headers);
  requestHeaders.set("x-local-currency", currency);

  const { pathname } = request.nextUrl;
  const accessToken = request.cookies.get("access_token")?.value;

  // Redirect authenticated users away from /login.
  if (pathname === "/login" && accessToken) {
    return NextResponse.redirect(new URL("/dashboard", request.url));
  }

  // Guard protected routes.
  const isProtected = PROTECTED_ROUTES.some((route) => pathname.startsWith(route));
  if (isProtected && !accessToken) {
    return NextResponse.redirect(new URL("/login", request.url));
  }

  return NextResponse.next({
    request: { headers: requestHeaders },
  });
}

export const config = {
  matcher: ["/((?!api|_next/static|_next/image|favicon.ico).*)"],
};
```

> **Note:** The middleware `matcher` currently excludes `/api` — but the API routes (`/api/auth/login`, `/api/auth/refresh`, `/api/auth/logout`) need to be accessible. Since the matcher already excludes all `/api` paths, this is correct (the API routes are not middleware-guarded, they handle their own auth via HTTP-only cookies). The form POST to `/api/auth/login` bypasses middleware protection because the matcher excludes `/api/*`.

> **Self-healing:** If `useActionState` is not available in the installed React version (unlikely with `^19.1.0`), fall back to `useState` + manual `fetch` to `/api/auth/login`. The `useActionState` API is stable in React 19 RC.

## 8. Edge Cases & Error Handling

| Case | Handling |
|---|---|
| User submits empty username/password | Server Action returns `{error: "Username and password are required"}`. HTML5 `required` attributes also prevent submission. |
| Backend returns 401 (wrong credentials) | Return `{error: "Invalid credentials"}`. Display in UI. |
| Backend returns 403 (account locked) | Extract `error.message` from uniform error contract → display. |
| Backend returns 422 (validation) | Extract `details.errors` → display "Check your input" or specific field error. |
| Backend returns 500 | Display "An unexpected error occurred. Please try again later." |
| Network failure (backend down) | `fetch` throws → Server Action catches → returns `{error: "Network error"}`. |
| Network timeout | Same as network failure — `fetch` throws on timeout. |
| Refresh token expired (401 on `/api/auth/refresh`) | Clear localStorage, redirect to `/login`. |
| Cookie not set in dev (HTTP) | `secure` flag is conditional on `NODE_ENV === "production"` — omitted in dev. |
| User navigates directly to `/dashboard` | Middleware checks `access_token` cookie → 401 redirect to `/login`. |
| Form submitted during pending state | `isPending` from `useActionState` disables inputs and shows "Signing in…" on button. |
