## 2. PROJECT SCOPE & ARCHITECTURE BLUEPRINT

### 2.1 System Overview

The **Pharmacy Suite Modernization** project transforms a monolithic, tightly-coupled Tkinter desktop application into a **modern, decoupled, and type-safe distributed system**. The refactor preserves the business logic encoded in the existing SQLite databases (`pharmacy.db`, `inventory.db`) and the Flask licensing microservice (`license_gate.py`), while introducing a stateless FastAPI backend and a modular React 18 frontend.

**Core Value Proposition:** Digitally manage a pharmacy's entire operation — from receiving inventory with batch/expiry tracking, through point-of-sale transactions with FIFO deduction, to role-based access control and remote license management — via a decoupled, type-safe, multi-process architecture suitable for desktop packaging (Tauri/Electron).

### 2.3 Design Patterns

The backend will follow a **Layered/Clean Architecture** with clear separation, mirroring the patterns of the existing suite but with strict type contracts:

| Layer | Responsibility | Files |
|-------|---------------|-------|
| **API Layer** (`app.api.routers`) | HTTP request routing, Pydantic v2 validation, uniform error formatting | `*_route.py` |
| **Service Layer** (`app.services`) | Business logic, orchestration, workflow coordination | `*_service.py` |
| **Data Access Layer** (`app.core`) | SQLAlchemy 2.0 async ORM models, repository patterns, async sessions | `models.py`, `database.py`, `repositories.py` |
| **Shared Utilities** (`app.shared`) | Authentication, logging, config, error handling, typed contracts | `auth.py`, `config.py`, `logging.py`, `exceptions.py`, `schemas.py` |

**Patterns Used:**
- **Repository Pattern**: All database queries go through async repository classes, not directly through ORM in the service layer.
- **Dependency Injection**: FastAPI's `Depends()` system for injecting services, async database sessions, and auth context.
- **Type-Safe Contract Synchronization**: Every backend Pydantic v2 model has a synchronized frontend TypeScript interface (generated or hand-maintained in `src/types/contracts.ts`).
- **Microservice Isolation**: The Flask `license_gate.py` runs as an independent process on its own port; the FastAPI backend communicates with it only via HTTP, never by import.

### 2.4 Verifiable Goals (User Journeys)

These are the **only** user journeys the refactored application must support. Every feature must map to one of these goals:

| ID | Goal | Description |
|----|------|-------------|
| **G1** | **POS Checkout** | A cashier scans or searches for a medication, adds it to the cart, applies insurance or payment, and prints/emails a receipt. Inventory is deducted using FIFO (oldest batch first, respecting expiry), against the existing `inventory.db` schema. |
| **G2** | **Inventory Receiving** | A pharmacist receives a shipment from a supplier. They scan/enter product details, batch/LOT number, expiry date, quantity, unit cost, and supplier. The system creates new batch records in `inventory.db` and logs the transaction. |
| **G3** | **Inventory Management** | A pharmacist views current stock levels, filters by drug name, batch, supplier, or expiry status. The system displays low-stock alerts and expiring-soon warnings. |
| **G4** | **Role-Based Access** | An admin user manages the system. They create/edit/delete users, assign roles (Admin, Pharmacist, Cashier), and view audit logs. The system enforces permissions on every action (backed by `pharmacy.db`). |
| **G5** | **License Activation** | A new customer installs the software and activates it by entering a license key. The system validates the key against the isolated Flask `license_gate.py` microservice and binds it to the local hardware. |

## 4. DATA MODELS, SCHEMAS & STATE MANAGEMENT

### 4.1 Legacy Database Schemas (Preserved — Read Only Contract)

The refactored FastAPI backend interfaces directly with the **existing** `pharmacy.db` and `inventory.db` files. The SQLAlchemy 2.0 async models MUST mirror these exact legacy schemas — do not alter tables, columns, or types. Establish the schema by reading the existing DB files (via `sqlite3` introspection or reading any existing model definitions in the monolith) before writing ORM models.

**`inventory.db` (representative tables — verify against actual file):**
```sql

    id              INTEGER PRIMARY KEY AUTOINCREMENT,

    manufacturer    TEXT,
    unit_of_measure TEXT    NOT NULL DEFAULT 'each',
```

**`pharmacy.db` (representative tables — verify against actual file):** contains `users`, `receipts`, `receipt_items`, `audit_logs`, `licenses`, `settings` per the existing monolith schema. Read the live DB to capture exact columns before modeling.

### 4.2 SQLAlchemy 2.0 Async ORM Models

All models use SQLAlchemy 2.0-style `Mapped[]` annotations and async sessions via `aiosqlite`. Example (adapt field names to the actual introspected schema):

```python
class Medicine(Base):
    __tablename__ = "medicines"
    id: Mapped[int] = mapped_column(primary_key=True)
    name: Mapped[str] = mapped_column(index=True)
    description: Mapped[Optional[str]]
    manufacturer: Mapped[Optional[str]]
    unit_of_measure: Mapped[str] = mapped_column(default="each")
    is_controlled: Mapped[bool] = mapped_column(default=False)
    batches: Mapped[List["Batch"]] = relationship(back_populates="medicine")

class Batch(Base):
    __tablename__ = "batches"
    id: Mapped[int] = mapped_column(primary_key=True)
    medicine_id: Mapped[int] = mapped_column(ForeignKey("medicines.id"))
    batch_number: Mapped[str]
    expiry_date: Mapped[date]
    purchase_price: Mapped[float]
    selling_price: Mapped[float]
    quantity: Mapped[int] = mapped_column(default=0)
    medicine: Mapped["Medicine"] = relationship(back_populates="batches")
```

Each ORM model has a 1:1 Pydantic v2 schema (`Create` / `Read` / `Update`) in `app/shared/schemas.py`. No model or schema may be left with `...` bodies.

### 4.3 State Management — Backend

The backend is **stateless**. All session state is maintained client-side via JWT tokens.

1. **Async Database Session**: Managed via `app/core/database.py` using FastAPI's dependency injection (`get_pharmacy_db`, `get_inventory_db`). Sessions are per-request and auto-closed.
2. **Configuration**: `app/shared/config.py` uses Pydantic `BaseSettings` loaded once at startup.
3. **License Isolation**: The FastAPI backend never imports `license_gate.py`. It calls `LICENSE_GATE_URL` over HTTP (via `httpx.AsyncClient`) as a separate microservice.
4. **Application State**: The FastAPI app (`app/main.py`) initializes services once at startup; no per-request mutable global state.

### 4.4 State Management — Frontend

The frontend uses **Zustand** for centralized, modular state management:

| Store | Responsibility |
|-------|----------------|
| `useAuthStore` | User session (token, user object, role, permissions), login/logout, token refresh |
| `useCartStore` | POS cart (items, quantities, totals, applied discounts, insurance info) |
| `useInventoryStore` | Medicine catalog, batch list, low-stock alerts, search/filter state |
| `useLicenseStore` | License status, activation status, grace period countdown |
| `uiStore` | UI preferences (theme, sidebar state, active tab, modal states) |

All store state shapes MUST be declared as explicit TypeScript `interface` types synchronized with the backend Pydantic models in `src/types/contracts.ts`.

### 4.5 Type Contract Synchronization

- **Backend**: Pydantic v2 models in `app/shared/schemas.py` are the single source of truth.
- **Frontend**: `src/types/contracts.ts` exports TypeScript interfaces mirroring every Pydantic model. Axios responses are typed via these interfaces. Zod schemas in `src/validation/` mirror them for runtime safety.
- **Anti-`AttributeError` Guarantee**: No dynamic attribute access crosses a boundary. Every API payload is validated by Pydantic on ingress and typed by a TS interface on egress. This eliminates the legacy `AttributeError` class of bugs.

### 5.6 HTTP Status Code Protocol

| Code | Meaning | When Used |
|------|---------|-----------|
| `200 OK` | Success | All successful GET, PUT, DELETE, and non-creation POST |
| `201 Created` | Resource created | Successful POST that creates a new resource |
| `400 Bad Request` | Client error | Invalid input, missing fields, validation failure |
| `401 Unauthorized` | Auth required | Missing/invalid/expired JWT token |
| `403 Forbidden` | Permission denied | Authenticated but insufficient role/permission |
| `404 Not Found` | Resource missing | Invalid resource ID |
| `409 Conflict` | Duplicate/conflict | Email already registered, batch already exists |
| `422 Unprocessable Entity` | Validation error | Pydantic v2 model validation failure (auto-generated by FastAPI) |
| `500 Internal Server Error` | Server error | Unexpected exception, DB failure |
| `502 Bad Gateway` | Upstream failure | Flask `license_gate.py` unreachable or returned invalid response |

### 5.7 CORS & Security Headers
- **CORS**: Configured to allow only the frontend origin (`FRONTEND_URL` env var). Credentials (cookies) allowed.
- **Security Headers**: All non-API responses must include `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Strict-Transport-Security` (in production).

## 7. ERROR HANDLING & SECURITY PROTOCOLS

### 7.1 Error Handling Strategy

#### Backend — Uniform JSON Error Contract (MANDATORY)

Every error — validation, auth, not-found, DB, or upstream microservice failure — MUST be returned in this exact shape:

```json
{
  "error": {
    "code": "STR",
    "message": "STR",
    "details": {}
  }
}
```

`code` is a stable snake_case string (e.g., `"insufficient_stock"`, `"license_unreachable"`). `details` is a free-form JSON object (may be empty `{}`).

Custom exceptions in `app/shared/exceptions.py`:

```python
class AppException(Exception):
    def __init__(self, message: str, status_code: int = 500, error_code: str = "app_error", details: dict = None):
        self.message = message
        self.status_code = status_code
        self.error_code = error_code
        self.details = details or {}
        super().__init__(self.message)

class ValidationError(AppException):
    def __init__(self, message: str, details: dict = None):
        super().__init__(message, status_code=400, error_code="validation_error", details=details)

class InsufficientStockError(AppException):
    def __init__(self, medicine_name: str, available: int, requested: int):
        super().__init__(
            f"Insufficient stock for {medicine_name}: {requested} requested, {available} available",
            status_code=400,
            error_code="insufficient_stock",
            details={"medicine_name": medicine_name, "requested": requested, "available": available},
        )

class LicenseGatewayError(AppException):
    def __init__(self, message: str, details: dict = None):
        super().__init__(message, status_code=502, error_code="license_unreachable", details=details)
```

A global FastAPI exception handler catches all `AppException` subclasses and returns:
```json
{ "error": { "code": "insufficient_stock", "message": "...", "details": { "medicine_name": "...", "requested": 5, "available": 0 } } }
```
with the corresponding `status_code`.

#### Frontend — Global Error Boundary
Top-level `ErrorBoundary` displays a friendly error page with "Retry" and support link. Axios response interceptor:
1. `401` → silent token refresh.
2. `403` → redirect to "Access Denied" page.
3. `4xx`/`5xx` → toast with parsed `error.message` from the uniform contract.
4. Network error → "Unable to reach server."

### 7.2 Security Protocols

#### Input Sanitization
- **Backend**: All Pydantic v2 models enforce type, length, and pattern. No raw SQL — SQLAlchemy parameterized async queries only.
- **Frontend**: Zod schemas mirror backend; re-validated server-side.
- **HTML Output**: Sanitize any user HTML via `bleach` before storage/rendering.

#### Microservice Isolation
- Flask `license_gate.py` runs as a **separate process** on `LICENSE_GATE_PORT` (default 5000).
- FastAPI backend reaches it exclusively via `httpx.AsyncClient` to `LICENSE_GATE_URL`.
- No shared import graph, no shared in-process state, no shared DB connection between the two processes.
- If the microservice is unreachable, FastAPI returns `502` with `{"error": {"code": "license_unreachable", "message": "...", "details": {}}}`.

#### Secrets Management
- Secrets (JWT secret, license secret) read from environment via Pydantic Settings. `.env` in `.gitignore`.
- No secrets in logs, errors, or client code.

#### Password Security
- bcrypt (cost 12) via `passlib`. Min 8 chars, upper+lower+number.
- 5 login attempts/min per IP + account; failures logged.

#### JWT Security
- Access 8h, refresh 30d. Secure HttpOnly SameSite=Strict cookies.
- HS256 exclusively. Secret ≥ 64 random chars.

#### Audit Logging
All significant actions logged to `audit_logs` in `pharmacy.db`: login/logout, POS checkout, inventory receive/adjust, user role change, license validation, settings change. Each entry: user_id, action, resource_type, resource_id, details (JSON), ip_address, timestamp.

#### Secure Headers
```
X-Content-Type-Options: nosniff
X-Frame-Options: DENY
X-XSS-Protection: 1; mode=block
Referrer-Policy: strict-origin-when-cross-origin
Strict-Transport-Security: max-age=31536000; includeSubDomains
Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'
```
